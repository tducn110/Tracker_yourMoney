# 🚀 Implementation Plan: Finance Service Optimization & Refactoring

This document outlines the step-by-step plan to fix performance issues, logical inconsistencies, and technical debt in the Budget, Goal, and Bill services of the S2S Finance API.

---

## 📊 Comparison & Audit Summary

| Component | Current Issue | Proposed Solution | DB Impact |
|-----------|---------------|-------------------|-----------|
| **Budgets** | `walletScope` column is unused and confusing. | Remove `walletScope` from schema and API. | Drop column |
| **Budgets** | In-memory aggregation of thousands of transactions. | Use Drizzle `sql` aggregations (`SUM`, `BETWEEN`). | Performance optimization |
| **Goals** | Contributions logged as `expense` (incorrect net worth). | Change contribution type to `transfer`. | Logic change |
| **Goals** | Hardcoded category string "Tiết Kiệm". | Use system category ID or constant mapping. | Refactoring |
| **API** | `debug.ts` contains dead Firebase/connectivity code. | Delete the file and cleanup routes. | Code cleanup |
| **General** | Standardized errors missing in some services. | Use `NotFoundError`, `ConflictError` classes. | Quality improvement |

---

## 🛠 Phase-to-Phase Implementation

### Phase 1: Database & Schema Cleanup
*   **Task 1.1: Drop Unused Columns**
    - [ ] Remove `walletScope` from `packages/db/src/schema/budgets.ts`.
    - [ ] Update `packages/shared-schemas` to remove `walletScope` from Zod schemas.
    - [ ] Generate and run migration: `pnpm db:generate` & `pnpm db:migrate`.
*   **Task 1.2: Delete Dead Code**
    - [ ] Remove `apps/api/src/routes/debug.ts`.
    - [ ] Remove debug route registration in `apps/api/src/server.ts`.

### Phase 2: Budget Service Optimization (The "S2S" Engine)
*   **Task 2.1: Refactor `getBudgetSummary`**
    - [ ] Replace `db.query.transactions.findMany` with a `db.select({ total: sql`SUM(amount)` })` query.
    - [ ] Group by `categoryId` and filter by `userId` + `startDate/endDate` in SQL.
    - [ ] Implement `Decimal.js` for final rounding at the service layer.
*   **Task 2.2: Refactor `getBudgets`**
    - [ ] Optimize the loop that calculates progress for each budget.
    - [ ] Use a single batch query to get spending for all active budgets instead of N queries.

### Phase 3: Goal Service - Financial Accuracy
*   **Task 3.1: Fix Transaction Type**
    - [ ] In `goal-service.ts`, change transaction type from `expense` to `transfer` when adding to a goal.
    - [ ] Update `currentSaved` calculation to correctly reflect transfer-in logic.
*   **Task 3.2: Category Identification**
    - [ ] Create a utility to resolve the "Savings" category ID without relying on the Vietnamese string "Tiết Kiệm".

### Phase 4: Bill Service & Security Audit
*   **Task 4.1: Aggregation Check**
    - [ ] Verify `bill-service.ts` correctly handles partial payments using SQL `SUM`.
    - [ ] Ensure all queries are strictly scoped by `userId`.
*   **Task 4.2: Idempotency Implementation**
    - [ ] Verify `Idempotency-Key` handling for bill payments to prevent double-charging users during network lag.

### Phase 5: Refactoring & Clean Code
*   **Task 5.1: Error Handling Standard**
    - [ ] Replace `Object.assign(new Error(...), { status: 404 })` with `throw new NotFoundError(...)`.
*   **Task 5.2: Service Splitting**
    - [ ] If `BudgetService` exceeds 600 lines, split into `BudgetQueryService` and `BudgetCommandService`.

---

## 🛡 Security & Precision Checklist
- [ ] **No Floats**: Every calculation uses `Decimal.js`.
- [ ] **User Isolation**: `userId` check in every `WHERE` clause.
- [ ] **Audit Trail**: Every goal completion logs an entry in `audit_logs` (if implemented) or updates `updatedAt`.
- [ ] **Input Validation**: All parameters validated by `@finance/shared-schemas`.
